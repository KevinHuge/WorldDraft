# Evaluating your own method

This guide scores the videos generated by your method and builds the benchmark tables. Text in angle brackets
(`<...>`) is a placeholder. Commands marked [GPU] need a GPU. Run everything from the repository root.

## 1. Environments

| environment | used for | requirements |
|---|---|---|
| eval | inventory, aggregation, tests | `eval/requirements.txt` (Python 3.11) |
| judge | QA and event questions (Qwen3.6-27B on vLLM; about 80 GB GPU memory per worker) | `eval/requirements-judge.txt` (Python 3.12) |
| track | geometry (SAM 3, SAM 2, DINOv2) | `eval/requirements-track.txt` (Python 3.12) |
| quality | image quality, aesthetic quality, CLIP | `eval/requirements-quality.txt` (Python 3.11) |
| ViPE | camera trajectories | official ViPE 1.2.0 environment + `eval/requirements-camera.txt` |

```bash
python3.11 -m venv .venv-eval && .venv-eval/bin/pip install -r eval/requirements.txt

python3.12 -m venv .venv-judge
.venv-judge/bin/pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu128
.venv-judge/bin/pip install -r eval/requirements-judge.txt

python3.12 -m venv .venv-track
.venv-track/bin/pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu126
.venv-track/bin/pip install -r eval/requirements-track.txt

python3.11 -m venv .venv-quality
.venv-quality/bin/pip install torch==2.4.1 torchvision==0.19.1 --index-url https://download.pytorch.org/whl/cu121
.venv-quality/bin/pip install -r eval/requirements-quality.txt
bash eval/download_quality_weights.sh          # MUSIQ, CLIP and LAION weights -> ~/.cache/worlddraft/vbench-quality

git clone --branch v1.2.0 https://github.com/nv-tlabs/vipe.git <vipe checkout>
# install ViPE following its README, then add: <vipe python> -m pip install -r eval/requirements-camera.txt
```

Write the interpreters into `eval/configs/envs.local.yaml` (not tracked; it overrides `eval/configs/envs.yaml` key by key):

```yaml
python:
  qa: .venv-judge/bin/python
  events: .venv-judge/bin/python
  geometry: .venv-track/bin/python
  camera: <vipe python>
  quality: .venv-quality/bin/python
  report: .venv-eval/bin/python
gpus: [0, 1, 2, 3]
vipe_root: <vipe checkout>
```

Weights are downloaded from Hugging Face on first use: `Qwen/Qwen3.6-27B`, `facebook/sam3` (gated: request access, then
`hf auth login`), `facebook/sam2.1-hiera-large`, `facebook/dinov2-base` and the `kernels-community/cv-utils` kernel.
To use copies that already exist on your machine, map the ids to directories under `models:` in `envs.local.yaml`.
`ffmpeg` must be on `PATH`.

## 2. Data

```bash
bash eval/download_data.sh                # data/gt and data/drafts; add --with-scenes for the Blender scenes
```

`data/drafts/<case>/<case>_<cell>/<case>_<cell>.mp4` are the 432 draft videos (48 scenes `A01`...`F08`, nine cells
`P0_AN` ... `P2_AC`; 832x480, 81 frames, 16 fps), each with `preprocessing.json`; `data/drafts/<case>/target_prompt.txt`
is the target prompt shared by the nine cells of a scene. Set `WORLDDRAFT_DATA` to keep the data elsewhere.

## 3. Generated videos

Condition your model on each draft video with its scene's target prompt and store the output as

```
<videos>/<model>/<case>/<cell>/output.mp4
```

for example `videos/my_model/A01/P1_AN/output.mp4`. Any resolution and frame rate is accepted; the first five seconds
are evaluated. Missing cells are recorded as missing, not as zero.

Register the model in `eval/configs/models.yaml` with how it receives the 832x480 draft (`transform`: whole-canvas
resize, centre crop, letterbox, ...). Boxes of the ground truth are mapped to your output frame with it; the evaluation
refuses unregistered models.

## 4. Evaluate [GPU]

```bash
bash eval/eval.sh --videos <videos> --models my_model --out eval/results/my_model
```

This freezes `inventory.json`, runs the five stages and writes `eval/results/my_model/report/`. Options:
`--stages qa events geometry camera quality` (any subset), `--gpus 0 1 2 3`, and `--sam2-cpu-state` (keep SAM 2
tracking state in host memory when the geometry stage runs out of GPU memory). A stage alone:

```bash
PYTHONPATH=eval python -m worlddraft_eval.stages geometry --out eval/results/my_model
```

Rerunning the same command resumes unfinished work from the frozen plans. To evaluate a different set of videos, use a
new `--out` directory.

## 5. Outputs

Each stage writes `<out>/<stage>/per_video.csv` in one long format, `model,case,cell,metric,value,status`
(`value` on its internal scale: proportions in 0-1, CLIP as cosine x100, camera errors in their own units). The raw
judge answers, evidence images and tracks stay in the stage directories. `<out>/report/` holds `result.md|html` and
`tables/` (`full_grid.csv`, `canonical_P1_AN.csv`, `grid_<metric>.csv`, `all_models.csv`, `per_case.csv`, ...).
